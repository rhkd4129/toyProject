2. FastAPI S3 로직 전체 주석처리 (pdfRouter.py:9-18)
# 전부 주석 → FastAPI가 실제로 S3에서 PDF를 다운받지 않음
PdfRequest.py에 presignedDownloadUrl + presignedUploadUrl 두 개를 받도록 설계되어 있는데, 라우터에서 실제로 사용하지 않음.

3. presigned 업로드 URL이 없음

현재 Spring은 S3 업로드 후 다운로드용 presigned URL만 반환함.
FastAPI가 처리 결과(XLSX)를 S3에 올리려면 업로드용 presigned PUT URL도 필요한데, S3StorageService에 그 로직이 없음. 설계 의도는 이랬을 것:

Spring → FastAPI에게 { presignedDownloadUrl(PDF 다운로드), presignedUploadUrl(XLSX 업로드) } 전달
FastAPI → presignedDownloadUrl로 PDF 다운로드
FastAPI → 처리 후 presignedUploadUrl로 XLSX 업로드
FastAPI → Redis에 resultPath 전달
Spring  → Vue에 SSE

  문제 2 (숨겨진 구조적 버그) — Redis가 DB 커밋보다 먼저 실행됨

  PdfService.java 로그 순서를 보면:
  01:06:23.801 → Redis 메시지 전송 완료 (id: 1781280383413-0)
  01:06:23.802 → DB INSERT 시도
  01:06:23.819 → DB INSERT 실패 → 트랜잭션 롤백

  @Transactional 안에서 Redis가 먼저 실행되고 나중에 DB 커밋 시점에 INSERT가 실행됩니다. DB 실패로 트랜잭션은 롤백되지만 Redis 메시지는 이미 전송돼서 취소가 안 됩니다. FastAPI는 존재하지 않는 taskId로 작업을 시작하는
  상황이 생길 수 있어요.

  수정 방법은 Redis 전송을 DB 커밋 이후로 미루는 것입니다.
