온프레미스 → IaaS → PaaS → CaaS → 서버리스
관리 복잡                        클라우드 위임


온프레미스 (On-Premises)
서버를 내 회사 건물 안에 직접 두는 방식.
하드웨어 구매부터 OS 설치, 네트워크 설정, 보안 패치까지 전부 담당.
통제권이 가장 높지만 그만큼 비용과 운영 부담도 큼
금융·공공기관처럼 데이터를 외부로 못 내보내는 경우에 많이 사용

IaaS — Infrastructure as a Service
AWS EC2, Azure VM 같은 개념.
서버 물리 장비는 클라우드가 갖고 있지만,
그 위에 OS 깔고 미들웨어 설정하고 보안 업데이트하는 건 여전히 내가 함.
 "서버를 빌려 쓰는" 느낌. 온프레미스보다 초기 비용이 낮고 필요할 때 서버를 늘리거나 줄일 수 있다


PaaS — Platform as a Service
Heroku, Google App Engine 같은 것.
OS나 런타임 관리도 클라우드가 해줘서, 개발자는 코드만 올리면 돌아감.
"내 앱만 신경 쓰면 된다"는 게 장점이지만, 플랫폼이 정해준 방식대로만 해야 해서 자유도가 떨어짐


컨테이너 서비스 (CaaS) — Container as a Service
쿠버네티스(Kubernetes) 기반의 EKS, GKE 같은 것
Docker 컨테이너로 앱을 감싸서 올리면 클러스터 관리는 클라우드가 해줌.
PaaS보다 유연하고, IaaS보다 편하다는 점에서 요즘 기업들이 가장 많이 선택하는 중간 지점


서버리스 (Serverless / FaaS)
AWS Lambda, Cloudflare Workers 같은 .
서버 자체를 전혀 신경 안 써도 됨.
함수 코드만 올려두면, 요청이 들어올 때만 실행되고 끝나면 사라짐.
서버가 없는 게 아니라 내가 서버를 의식하지 않아도 된다는 뜻.
트래픽이 불규칙하거나 특정 이벤트에만 반응하는 기능에 적합
